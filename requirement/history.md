  一、设计哲学

  六位专家的构想高度收敛，形成三条核心原则：

  ▎ 1. 时间因果律是铁律 — 系统在架构层强制执行，不依赖人工自律
  ▎ 2. 回测即实盘 — 两者共享 95% 代码路径，只换数据源和执行层
  ▎ 3. 风控是唯一网关 — 策略无法绕过风控直接下单

  二、系统架构

  整体模式：事件驱动分层单体

  ┌─────────────────────────────────────────────────────┐
  │                   Trading Engine                     │
  │                                                      │
  │  DataFeed  →  Strategy  →  RiskGate  →  Execution   │
  │     ↓              ↓           ↓            ↓        │
  │  BarEvent    SignalEvent   OrderEvent    FillEvent   │
  │                                ↓                     │
  │                          Portfolio                   │
  │                                ↓                     │
  │                          Analytics                   │
  └─────────────────────────────────────────────────────┘
       历史模式：CSVFeed / YahooFeed + SimulatedExecution
       实盘模式：IBKRFeed              + IBKRExecution
                ↑ 只替换这两个，其余代码路径完全共享 ↑

  五大核心 Protocol（唯一稳定契约）

  DataFeed    : subscribe(symbols, bar_size) → AsyncIterator[BarEvent]
  Strategy    : on_bar(bar, portfolio_view)  → list[SignalEvent]
  RiskChecker : check(signal, portfolio_view)→ OrderEvent | None
  Execution   : submit(order)               → FillEvent
  PortfolioView: position/cash/equity        → 只读视图

  原始层 (Raw)         → 清洗层 (Clean)       → 特征层 (Feature)

  Point-in-Time 核心设计

  每条数据必须携带双时间戳：
  - event_time：数据描述的业务时间（如财报期末 2024-09-30）
  - known_time：数据被公开入库的时间（如 SEC 实际申报日 2024-11-14）

  回测引擎查询数据时传入 as_of_date，数据层强制过滤 known_time <= as_of_date，彻底杜绝前视偏差，无需依赖代码审查。

  整合进系统的四层架构

  Strategist 给出的双层架构非常清晰，我在此基础上确认为系统正式设计：

  Layer 0: 宏观状态识别（独立模块）
  ─────────────────────────────────────────
  输入：收益率曲线斜率(10Y-2Y) + 信用利差(IG-OAS) + VIX
  输出：Regime 标签 × 置信度
        [Risk-On / Risk-Off / Stagflation / Reflation / Goldilocks]
  更新：日频

          ↓ 条件权重表（不直接混合打分）

  Layer 1: 外因 Beta 管理
  ─────────────────────────────────────────
  输入：全球跨资产宏观动量（股/债/商品/汇率）
  输出：资产类别方向约束 + Beta 暴露上限
  作用：战争/关税/加息 这类事件在这里被捕获，
        告诉内因层"此时不允许做多高Beta股"

          ↓ 方向约束 + 允许交易的资产范围

  Layer 2: 内因 Alpha 挖掘
  ─────────────────────────────────────────
  输入：品种截面因子（基本面/技术/情绪）
  处理：在 Layer 1 允许的范围内，IC_IR 加权合成得分
        行业/市值中性化（剥离残留外因影响）
  输出：具体品种的多空排名

          ↓

  Layer 3: 组合构建 + 风控
  ─────────────────────────────────────────
  风险平价权重 + 换手成本约束 + Beta 监控

  关键原则：外因和内因不能合并为单一打分，必须分层处理——两者更新频率不同、操作对象不同（ETF/期货 vs 个股），混合打分会破坏行业中性化的意义。

  ---
  Regime × 因子权重的联动

  Regime 识别模块独立运行，通过条件权重表影响内因层：

  ┌─────────────┬──────────┬──────────┬──────────┐
  │   Regime    │ 动量权重 │ 价值权重 │ 质量权重 │
  ├─────────────┼──────────┼──────────┼──────────┤
  │ Risk-On     │ 1.5×     │ 0.8×     │ 1.0×     │
  ├─────────────┼──────────┼──────────┼──────────┤
  │ Risk-Off    │ 0.5×     │ 1.2×     │ 1.5×     │
  ├─────────────┼──────────┼──────────┼──────────┤
  │ Stagflation │ 0.7×     │ 0.6×     │ 1.8×     │
  ├─────────────┼──────────┼──────────┼──────────┤
  │ Reflation   │ 1.3×     │ 1.4×     │ 0.9×     │
  └─────────────┴──────────┴──────────┴──────────┘

  这解决了一个关键问题：同一个"动量因子"，在 Risk-On 环境下有效，在 Risk-Off 环境下可能是陷阱。静态因子权重无法处理这种情况，而 Regime 驱动的动态权重可以。
